# Copper 支持矩阵

> 这张表的唯一目的：**让你一眼知道什么能跑、什么不能跑**。  
> 不确定的地方不写"大概支持"，只写实测结论。

更新时间：2026-10-31 · 内核版本：float-lang 0.2.0 · IDE 0.19.0

图例：**✅ 完整** / **🟡 部分**（有边界） / **❌ 未实现**（会明确报错，不会静默）

## 一、执行引擎

|              | Rust 内核（`float-lang`） | TS 兼容引擎（旧解释器） |
| ------------ | --------------------- | ------------- |
| F5 运行        | ✅ 默认走这条               | 仅在需要时兜底       |
| F6 调试（断点/单步） | ❌                     | ✅             |
| 速度           | 比 CPython 快 1.2~5 倍   | 比 CPython 慢   |
| 状态           | **主引擎**               | 逐步退役中         |

F5 的路线：**`class` / `try` / `import` / `new` / `ask` 全部走 Rust 内核**，一条实现到底，没有"兼容引擎"这回事。  
`ask` 的做法：内核跑到提问处**先停下**，把问题交给控制台，你答完它把答案补进输入、从头重跑
（脚本对同样输入是确定性的，重跑即同一条路径）。F6 断点调试仍走旧解释器。

### 标准库（`import 库名`，已实现）

写 `import os` / `import data` 这样的行就等于"要用这个库"，**不读文件、不下载、不装包**。
解析器把 `os.readfile` 收敛成一个内建名，所以 F5（Rust 内核）、F6（解释器）、AOT 三条路行为一致。

| 库 | 函数数 | 代表 | 全平台？ |
|---|---:|---|---|
| `os` | 32 | `readfile writefile listdir makedir cwd getenv pathjoin basename dirname extname abspath runcmd pid platform sleep` | 文件/进程类要桌面版；路径类是纯运算 |
| `data` | 26 | `sort sort_by max min sum avg median stdev count freq unique flatten chunk zip enumerate slice keys values entries merge pick omit get` | ✅ |
| `json` | 5 | `parse stringify pretty valid try_parse` | ✅ |
| `time` | 12 | `now timestamp millis sleep mark since format parse parts add diff iso` | ✅ |
| `random` | 8 | `rand float choice shuffle sample seed gauss weighted` | ✅（`seed` 后序列可复现） |
| `ui` | 10 | `color bar title table progress clear clear_line` | ✅ |
| `re` | 7 | `findall match search test replace split escape` | ✅ |
| `net` | 10 | `fetch post download request encode decode query ip` | 桌面版 |

要点：

- 参数错了当场报错并说清楚要什么：`data.avg 需要数字，得到 "a"`、`data.chunk 的每块长度要大于 0`；
- 库里不存在的函数在**解析期**就拦住：`os.nothing(1)` → `os 里没有 nothing 这个函数`，不会留到运行时；
- `import os` 这一行换成空语句，**行号不变**（报错定位、断点仍然准）；
- 旧名字（`readfile` / `now` / `fetch` …）全部保留，`os.readfile` 与 `readfile` 是同一个实现；
- `random.seed(n)` 之后序列是确定的，两个引擎跑出来一模一样（对拍能逐字比）；
- 明确没做：`net.listen` / `net.server_close` / `ui.menu` / `ui.input` / `ui.spinner`，调用时会明确说明原因。

## 四·五、alias / `#define`（类 #define 的文本替换）

```cw
alias 你好 = print("你好，世界")
你好                      // 展开成 print("你好，世界")

#define 双倍 x * 2
int x = 21
print(双倍)               // 42
```

- 两种英文写法：`alias 名字 = 内容`、`#define 名字 内容`（中文 `换 名字 成 内容` 兼容）；
- 这一行**之后**所有出现「名字」的地方（**整词**匹配）都换成「内容」；
- 纯文本级替换，内容可以是任意代码片段（表达式、整条语句都行），不用是合法的值；
- **行号不会错位**：定义行变成空行，替换都在同一行内完成，报错的行号仍是用户看到的那一行；
- 支持重新定义（后面的覆盖前面的）、支持链式展开（`a → b`、`b → 9`）；
- 自己引用自己（`alias 你好 = print("你好")`）按普通文字处理；两个别名互相指（`a → b`、`b → a`）会明确报错，不会死循环。

## 指针：C 的能力，没有 C 的坑

指针在这一版**改成了"拿得到裸地址"**：地址是一个能打印（`0x7F0000000000`）、能加减、能比较的值，
但背后仍然记着"哪块内存的第几格"，所以算不出野指针——越界 / 悬空 / free 之后再访问都是明确报错。

写法上**没有 `&`、`*`、`->` 这一堆符号**，只有三个词：

| 能力 | 写法 | 说明 |
| --- | --- | --- |
| 取地址 | `addr(x)` | 指向变量本身，读写都回到 x |
| 取元素地址 | `addr(xs, i)` | 指向列表那一格（共享，不是拷贝） |
| 读 | `read(p)` | 读出当前那一格 |
| 写 | `write(p, 值)` | 写回当前那一格（只能单独成句） |
| 地址运算 | `p + 1` / `p - 1` / `p - q` | 挪一格 / 两地址相减得隔了几格（一格 8 字节） |
| 相对下标 | `p[k]` | 等价 `read(p + k)`，负数往回 |
| 手动内存 | `alloc(n)` / `free(p)` | 只有 alloc 出来的块才允许 free |

```copper
addr total = alloc(2)
write(total, 10)
write(total + 1, 20)
print(read(total))          /* 10
print(total)                /* 0x7F0000000000

int n = 5
addr p = addr(n)
write(p, 9)
print(n)                    /* 9
```

老写法 `&x` / `*p` / `*p = 值` **仍然能跑**（老脚本不用改），但 IDE 会给黄色提示建议换成
`addr` / `read` / `write`——一门语言里两种指针风格混着写，读别人的代码就费劲了。

`for v in p` 从当前格遍历到末尾；`len(p)` 是"从当前位置到末尾还剩几格"。
悬空指针（指向已经返回的函数的局部变量）会在 `read` 时报"已经离开作用域"。

当前 AOT 还不编译"通过地址写入"（`write`），遇到会明确报告并回落到 VM 跑——结果一样，只是慢一点。

## 生态：异常、并发、包管理到哪一步了

这三件事最容易被问"你们是不是只有个玩具语言"。现状写清楚，不含糊：

| 方面 | 状态 | 到底有什么 |
| --- | --- | --- |
| 异常 | ✅ 够用 | `try / catch e / finally / throw`；**运行时错误也能接住**（除零、越界、调用太深…）；`catch e` 拿到的是 `{消息, 行, 类型}` 字典；`throw` 抛什么就原样接什么（可以抛字典、列表） |
| 并发 | ❌ 没有 | 不打算做线程/async。脚本是单线程顺序执行的，`wait` 只做延时。并发要靠外部程序 + `os.runcmd` / `net.*`，语言层不假装有 |
| 包管理 | ⚠️ 本地版 | 有 `packages/` 目录约定：把一包脚本拖进去就自动检测、可多版本共存、可一键切版本回滚（`manifest.json` 里写 name/version/entry/runtime）。**没有**在线仓库和依赖解析——标准库自带、第三方靠拷目录 |
| 模块 | ✅ | `import "库.co"` 编译期就地摊平（零运行时开销、支持套娃/去重/循环检测）；`import os` 这种裸名是标准库 |
| 标准库 | ✅ | 8 个库 110 个函数（os/data/json/time/random/ui/re/net），`import` 即用，不用装 |

一句话：**它是一门"带 IDE 的完整脚本语言"，不是教学玩具**——但也不是通用系统语言。
没有线程、没有在线包仓库，这是设计取舍，不是没做完。

## 语义速查：容易被问到的，一次说清

| 问题 | 定义 |
| --- | --- |
| `1 === 1.0` 是 true 吗？ | **是**。数字只有一种类型（int/float 自动互通），`===` 比「类型 + 值」，数字类型相同就比大小；`==` 是深比较，列表/字典逐项比内容 |
| `-2**2` 等于几？ | **4**（等价 `(-2)**2`）——一元负号结合得最紧。想要 `-(2**2)` 就写括号。建议负数参与幂运算一律加括号 |
| `range(10**9)` 会怎样？ | `range` 返回**真列表**，十亿元素会直接吃满内存。大循环用 `while i < n`；惰性数列在规划里，做之前文档就这么写 |
| 类名能不能当函数调？ | **不能**。`Hero("阿方")` 会报错：`「Hero」是类名，要创建实例请写 new Hero(…)`——类名调用和函数调用长得一模一样，不强制就分不清 |
| `repeat(n)` 怎么计数？ | 只管次数，**没有循环变量**。要下标用 `for i in range(n)`。`repeat(3)` 就是「做三次」，别用它取 i |
| 为什么 for 不带括号？ | 故意的。`for x in 集合` 里集合自带词边界；`if / while / elif` 的条件是任意表达式，括号负责定界。语法图见下文 |
| `wait until(条件)` 是循环吗？ | 不是，它是**同步/等待原语**：阻塞当前脚本直到条件成立。归在「时间与等待」，不归循环 |
| `stop` 停什么？ | 终止整个脚本。原来的 `stop all / stop now / stop script` 已合并（写了会报错提示直接写 `stop`） |
| `fetch / post` 阻塞吗？超时？ | **同步阻塞**，宿主侧 10 秒超时；失败**抛错**，用 `try / catch e` 接（`e` 的消息里有网址和原因）。没有异步版 |
| `alloc / free` 到底是什么？ | 定位是**带边界检查的外部缓冲句柄**，不是第二套内存管理：块有固定格数，读写走 `read(p)` / `write(p, 值)`（就是 peek/poke），越界 / 悬空 / 重复 free 都报错，漏 free 脚本结束会点名。和 GC 不混用——alloc 的块永不自动回收 |
| `min / max` 只收两个参数？ | 不是。`min(3, 1, 2)` 多参数、`min([3, 1, 2])` 传一个列表，都行 |

## 逻辑关键字 and / or / not

`and` `or` `not` 是 `&&` `||` `!` 的关键字写法，**同一个 AST 节点，短路语义完全一致**：
左边能定结果就绝不算右边（`d.has("k") and d["k"] > 0` 是安全的写法）。

⚠️ **自定义函数做不到短路**：`AND2(a, b)` 的参数 a、b 会**先全部求值再调用**，
所以条件里"先判存在再取值"（`d.has("k")` 后面紧跟 `d["k"]`）必须用 `and`/`&&`，用函数包一层照样会崩。

## 类型（int 只是最常用的那一个）

**类型不是只有 `int`。** 一共 8 种写法，`int` 只是数值里最常见的那一档：

| 类型 | 装什么 | 例子 |
| --- | --- | --- |
| `int` | 整数 | `int hp = 100` |
| `float` | 小数 | `float rate = 0.85` |
| `str` | 文本 | `str name = "小方"` |
| `bool` | 真 / 假 | `bool ok = true` |
| `list` | 列表 | `list xs = [1, 2]` |
| `dict` | 字典 | `dict d = {"a": 1}` |
| `ptr` / `addr` | 指针（手动内存）；两个名字是同一个类型，`addr` 是新写法 | `addr p = alloc(8)` |
| `var` | 不限定（动态） | `var x = 任意值` |
| 类名 | 该类实例 | `Person p = new Person()` |

**类型标注是真的**（不是写着好看）：`int hp = "abc"`、`str s = 123`、`int n = 1.5`、
`int f()` 里 `return "x"`、类字段 `int n = "x"`、参数默认值 `fn f(int a = "x")`
都会**直接报错并拦住运行**，报错里写清"声明成什么、实际是什么、怎么改"。
赋值语句（`n = "x"`）只给**警告**——变量中途换内容是动态语言的常态，提醒但不拦。

放宽规则：`int` 可以放进 `float`（`float f = 1` 合法）；`var` 不检查；
推断不出来（比如 `int n = f()` 而 `f` 没写返回类型）就**闭嘴不报**，绝不瞎猜。

**函数返回类型写在函数名前面**，和变量声明一个写法：

```cw
int add(a, b)          /* 返回 int
    return a + b

void 说(内容)           /* 不返回值
    print(内容)

fn hi(x)               /* 不写类型：返回什么由 return 决定
    return "hi " + x
```

## 编辑器行为（补全 / 快捷键 / 读内存）

**光标语义（一个入口决定所有编辑器行为）**：`src/lang/context.ts` 的 `contextAt()` 用**词法 + AST**
判断光标在哪：注释 / 字符串 / `import "…"` 路径 / 正在起名字（声明·函数·类·循环·参数·字段）/
`对象.` 后面（含对象类型与所在类）/ 普通代码。补全、悬停、参数提示、重命名都问它，
所以**加新语法只要在 AST 里表达清楚，所有编辑器功能自动跟着对**，不用每处补一条正则。

**补全**（`Ctrl+Space` 手动唤出，或在 `.` 之后自动弹）：

| 规则 | 说明 |
| --- | --- |
| 绝不自动加括号 | 函数、方法、内置一律**只插名字**，参数显示在名字右边的灰字里；只有模板片段（`for range`、`class` 这类）才会插入整套骨架，并且排在列表最后，必须主动选 |
| 什么都补 | 本文件变量 / 函数 / 类 / 字段、import 进来的符号、类型关键字、内置函数、老式指令、特殊变量、模板片段、插件贡献 |
| 优先级 | 正在用的最前：本文件符号 → 类型/关键字 → 内置函数 → 老式指令 → 模板片段；同档里"前缀命中"的排前面 |
| 成员补全 | `对象.` 时：该类的字段/方法在前；基本类型（`str`/`list`/`dict`/`ptr`）只给对应的内建方法，不再一次甩出几十条不相干的 |
| 起名字时不打扰 | `int ▮` / `fn ▮` / `class ▮` / `for ▮` 后面不弹（你在造新名字） |
| 字符串/注释里不弹 | 唯一例外：`import "` 后面补工程里的 `.co` / `.cw` 文件名 |
| 残缺代码也补得到 | 解析器带**错误恢复**：`int hp = `（右边没写完）依然是 decl 节点，`fn f(a,` 依然是函数节点，名字不会丢——所以不需要拿正则在源码里再扫一遍 |

**快捷键**：`Ctrl+S` 保存（捕获阶段拦截，不会触发浏览器"保存网页"）、`Ctrl+Z / Ctrl+Y` 撤销重做、
`Ctrl+C / Ctrl+X / Ctrl+V` 复制剪切粘贴 —— 后四个走 Monaco 原生实现，全局快捷键处理器**不拦**它们。
`Ctrl+/` 注释用 `/*`（不是 `//`，那是整除）。

**几个老坑已修**：`a mod b` 等于 `a % b`（只在两个值中间这么写；`mod(a, b)` 仍是内建函数，汇编式 `mod a b` 也照旧）；`if` / `elif` 之间插注释或空行不再断链；
缩进没跟上会直接指出"第几行少缩进几个空格"，而不是过几行再报"这条语句看不懂"；
死循环判定从 200 万步放宽到 5000 万步（Rust 内核 2 亿），几百万次取模这类计算不会再被误杀。

**F6 调试也能读写文件**：桌面版里 `readfile / writefile / appendfile / hasfile` 在 F5 和 F6 下行为一致
（相对路径按工程目录解析）；浏览器预览里会提示"桌面版功能"。

**变量面板**：字典 / 列表 / 长文本默认截断显示，点"展开"看全量（展开区限高滚动，几千行也不撑爆面板）。

**只读内存**：运行（含 import 的库文件）、诊断、大纲、搜索、跳转定义、重命名、补全
全部读**编辑器缓冲区里的内容**——没存盘的改动也算数，不会读到磁盘上的旧版本。
