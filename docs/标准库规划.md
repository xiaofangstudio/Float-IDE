# Copper 标准库（v1）

> 状态：**已实现**（8 个库、110 个函数，三引擎同语义）。
> 本文档同时是**设计稿**和**函数表**：下面每一节列的函数都已经能用，
> 末尾「7. 实现状态」写了哪些是这一轮真正落地的、哪些明确没做。

## 0. 一句话背景

Copper 现在是图灵完备的，但**库太薄**：写个成绩统计要手撸冒泡排序，`fetch` 回来一段 JSON 只能
自己 `split`，没有正则、没有日期格式、没有随机抽样。Python 能活下来靠的是 `sorted` / `json` /
`re` / 标准库；Copper 缺的正是这一层。

所以 v1 的目标固定为：**`import 库名` 就能用，不用下载、不用装包**，覆盖「写脚本 / 做游戏」的
高频操作。第一批做 7 个（不含网络与图形），把 OS 从现有内建里拆出来独立成库。

## 2. 加载与命名：`import 库名`

### 2.1 规则

```copper
import os            /* 标准库：不读文件，注册命名空间 os
import "lib/工具.co"  /* 文件：老行为不变（编译期展开）
```

- **裸名字 = 标准库**（`import os` / `import json`），**带引号 = 文件**（`import "x.co"`）。
  两者共存，互不影响。
- 标准库**不打进用户工程**，也不写在工程 `packages/` 里 —— 它是 IDE / 内核自带的，升级 IDE 就升级库。
- 可选别名：`import json as j`（v1 先不做，留位）。

### 2.2 底层怎么实现（不引入新语法）

`os.readfile(x)` 在 AST 里是 `Call(callee = Member(Var("os"), "readfile"))`。
编译期做一次收敛：**`Member(Var(已知命名空间), 名字)` 且作为被调用者 → 直接当内建 `"os.readfile"`**。

- 三个引擎同一套规则：TS 解释器、Rust VM、AOT 都走 `call_builtin("os.readfile", args)`。
- 好处：不用给 VM 加新指令，AOT 也不用改（它本来就调 `call_builtin`）。
- 验收：`os.readfile(p)` 与 `readfile(p)` 结果必须逐字节相同。

### 2.3 旧名字永久兼容

迁移过去的函数**旧名一律保留**（`readfile` = `os.readfile` 的别名）：

- 老脚本一行不用改；
- 旧名**不进补全、不进文档、不进示例**（与中文关键字同一策略）；
- 新代码一律写带命名空间的版本。

### 2.4 每个新函数都要满足的四件事

1. `builtins.ts` 里有 spec（`sig` / `doc` / 参数个数）→ 补全、悬停、文档自动有；
2. `builtins.rs` 有同名实现，**错误文案与 TS 完全一致**（对拍会逐字比）；
3. `tests/parity/cases*.txt` 至少一条用例；
4. 走 `call_builtin`，AOT 自动可用（涉及回调的，如 `data.map(xs, fn)`，注明走 `call_named`）。

#### 示例

```copper
import os

list 文件 = os.listdir("data")
for 名 in 文件
    if os.extname(名) == ".csv"
        str 文本 = os.readfile(os.pathjoin("data", 名))
        print(名, len(文本))

dict r = os.runcmd("git status --short")
if r["code"] != 0
    print("git 出错：", r["out"])
```

#### 实现要点

- 全部走现有 `fsBridge`（TS 侧）/ `host.rs`（Rust 侧），不要各写一套 IO；
- `runcmd` 需要超时上限（沿用 10 秒档，可配），超时返回 `code: -1` 并在 `out` 里说明；
- 路径一律按脚本锚点解析，`chdir` 只改脚本锚点（老行为，不能改成进程 cwd）；
- `os.exit` 在 AOT 里就是 `std::process::exit`，语义一致。

### 3.2 `data` —— 列表 / 字典工具（不用手撸冒泡）

> 这是用户点名最狠的一个：「写成绩统计还得手撸冒泡」。

#### 排序与统计

| 函数 | 返回 | 说明 |
|---|---|---|
| `data.sort(列表, 方向?)` | list | 返回**新**列表，升序；`方向` 传 `"desc"` 降序。数字比数字，其余按字典序（与 `sorted` 同规则） |
| `data.sort_by(列表, 键, 方向?)` | list | 按字段排序；`键` 可以是字段名（`"分数"`）或单参函数；同一字段内保持稳定 |
| `data.max(列表)` | 任意 | 最大值（空列表报错「空列表没有最大值」） |
| `data.min(列表)` | 任意 | 最小值 |
| `data.sum(列表)` | 数字 | 求和；非数字元素报错并指出第几项 |
| `data.avg(列表)` | float | 平均；支持 `data.avg(列表, 键)` 按字段 |
| `data.median(列表)` | 数字 | 中位数（偶数取中间两个的平均） |
| `data.stdev(列表)` | float | 样本标准差 |
| `data.count(列表, 值)` | int | 出现次数 |
| `data.freq(列表)` | dict | 频次表 `{值: 次数}`（按首次出现顺序） |

#### 变换

| 函数 | 返回 | 说明 |
|---|---|---|
| `data.map(列表, fn)` | list | 对每项调用 `fn(项, 下标?)`，收集返回值 |
| `data.filter(列表, fn)` | list | 保留 `fn(项)` 为真的项 |
| `data.reduce(列表, fn, 初值?)` | 任意 | `fn(累计, 项)`；不给初值用第一项 |
| `data.groupby(列表, 键)` | dict | 按字段分组：`{键值: [项…]}`；键值按首次出现排序 |
| `data.index_by(列表, 键)` | dict | 按字段做索引；重复键后者覆盖 |
| `data.unique(列表)` | list | 去重（保序，值相等按 `==` 语义） |
| `data.flatten(列表, 层数?)` | list | 拍平嵌套列表，默认 1 层；`层数=0` 拍到底 |
| `data.chunk(列表, 每块长度)` | list | 切成若干块，最后一块可短 |
| `data.zip(a, b)` | list | 拉链成 `[[a1,b1], …]`，取短的 |
| `data.enumerate(列表, 起始?)` | list | `[[下标, 值], …]` |
| `data.reverse(列表)` | list | 返回反转后的**新**列表（不动原表） |
| `data.slice(列表, 起, 止?)` | list | 切片（负数从尾部算） |

#### 判断

| 函数 | 返回 | 说明 |
|---|---|---|
| `data.any(列表, fn)` | bool | 有一项满足就 true（短路） |
| `data.all(列表, fn)` | bool | 全部满足才 true（空列表 true） |
| `data.find(列表, fn)` | 任意 / null | 第一个满足的项；没有给 null |
| `data.find_index(列表, fn)` | int | 第一个满足的下标；没有给 -1 |
| `data.is_empty(列表 / 字典)` | bool | 空不空 |

#### 字典工具

| 函数 | 返回 | 说明 |
|---|---|---|
| `data.keys(字典)` | list | 键列表（按插入顺序） |
| `data.values(字典)` | list | 值列表 |
| `data.entries(字典)` | list | `[[键, 值], …]` |
| `data.merge(a, b)` | dict | 合并，`b` 覆盖 `a`；返回新字典 |
| `data.pick(字典, [键…])` | dict | 只留这些键（没有的忽略） |
| `data.omit(字典, [键…])` | dict | 去掉这些键 |
| `data.get(字典, 键, 默认?)` | 任意 | 取不到给默认（默认 `null`），**不报错** |

#### 示例（就是那个成绩统计）

```copper
import data

list 成绩 = [{"名": "阿方", "分": 93}, {"名": "小北", "分": 78}, {"名": "老陈", "分": 88}]

list 排行 = data.sort_by(成绩, "分", "desc")
for s in 排行
    print(s["名"], s["分"])

print("平均", data.avg(成绩, "分"))
print("中位", data.median([93, 78, 88]))
print("及格", len(data.filter(成绩, fn(s) return s["分"] >= 80)))
```

#### 实现要点

- `sort_by` 的 `键` 支持「字段名」和「函数」两种：字段名走快速路径，函数走 `call_named`；
- 排序**永远返回新列表**（和 `会改原表的 xs.sort()` 区分开，避免歧义）；
- 空列表的 `max/min/avg/median/stdev` 一律报错并说明是空列表，不要给 0 糊弄。

### 3.3 `json` —— 解析与序列化

> 痛点原文：`fetch` 回来是字符串，没有 `json.parse` 只能 `split`。

| 函数 | 返回 | 说明 |
|---|---|---|
| `json.parse(文本)` | 字典 / 列表 / 值 | 解析 JSON；对象 → 字典，数组 → 列表 |
| `json.stringify(值, 缩进?)` | str | 序列化；`缩进` 给数字就美化（`2` 两空格） |
| `json.pretty(值)` | str | 等价 `stringify(值, 2)` |
| `json.valid(文本)` | bool | 是不是合法 JSON（不抛错） |
| `json.try_parse(文本)` | dict | `{ok: true, value: …}` 或 `{ok: false, error: "…第 N 个字符"}` |

#### 错误约定

- `json.parse` 失败要指出**第几个字符**、期望什么：
  「JSON 第 42 个字符处应该是 `,` 或 `}`，实际是 `x`」；
- 数字按有无小数点区分 int / float（`3` → int，`3.0` → float）；
- 允许尾逗号？**不允许**（和标准 JSON 一致，避免和 Python 混）。
- 中文键、`\uXXXX`、`\n` 转义都要支持。

#### 与 AOT 的关系

AOT 里大表格用的 `parse_data(...)` 已经是同一套 JSON 子集的解码器 —— `json.parse` 复用它，
保证「AOT 编译的数据表」和「运行期 json.parse」行为一致。

#### 示例

```copper
import json
import net

str 文本 = net.fetch("https://example.com/api/score")
dict 数据 = json.parse(文本)
print(数据["name"], 数据["score"])
print(json.stringify(数据, 2))
```

### 3.4 `time` —— 日期 / 延时 / 计时

| 函数 | 返回 | 说明 |
|---|---|---|
| `time.now()` | str | 本地时间 `"2026-11-03 20:44:01"` |
| `time.timestamp()` | float | Unix 时间戳（秒，带小数） |
| `time.millis()` | int | 毫秒时间戳（等同现有 `now()`） |
| `time.sleep(秒)` | null | 延时；允许小数；负数报错 |
| `time.mark()` | int | 记一个计时起点（毫秒） |
| `time.since(起点)` | float | 距起点多少秒（`time.since(time.mark())`） |
| `time.format(时间戳, 格式?)` | str | 默认 `"YYYY-MM-DD HH:MM:SS"`；支持 `YYYY MM DD HH mm ss` |
| `time.parse(文本, 格式?)` | float | 解析成时间戳；格式不符报错 |
| `time.parts(时间戳?)` | dict | `{year, month, day, hour, minute, second, weekday, yearday}` |
| `time.add(时间戳, 秒)` | float | 加秒数（负数可以） |
| `time.diff(a, b)` | float | `b - a` 秒 |
| `time.iso(时间戳?)` | str | ISO8601：`"2026-11-03T20:44:01"` |

#### 说明

- 时区：v1 只用**本地时区**，`time.utc_*` 留到 v2（避免一上来就背时区库）；
- `weekday`：`1` = 周一 … `7` = 周日（和 ISO 一致，不是 0 起）；
- 已有 `now()` 保留为 `time.millis` 的别名。

### 3.5 `random` —— 随机扩展

| 函数 | 返回 | 说明 |
|---|---|---|
| `random.rand(最小, 最大)` | int | 闭区间随机整数（旧 `rand` 的别名） |
| `random.float()` | float | `[0, 1)` |
| `random.choice(列表)` | 任意 | 随机取一项；空列表报错 |
| `random.shuffle(列表)` | list | **原地**打乱并返回它（与 `xs.sort()` 就地风格一致） |
| `random.sample(列表, 个数)` | list | 不重复抽 `个数` 个；个数超长报错 |
| `random.seed(数)` | null | 固定种子（同种子同序列；调试/复现用） |
| `random.gauss(均值, 标准差)` | float | 正态分布 |
| `random.weighted(列表, 权重)` | 任意 | 按权重抽；权重和必须 > 0 |

#### 重要约定：`ask` 重跑与随机

F5（Rust 内核）的 `ask` 是「从头重放」，所以**同一次运行里种子必须固定**：
`random.seed` 之后重放会得到相同序列；不调 `seed` 则每次运行换种子。
这条要写进函数的 doc（IDE 悬停能看到），避免又踩 `13_pointer_game` 那个坑。

### 3.6 `ui` —— 控制台交互

> 目标：把「画菜单 / 清屏 / 进度条 / 上色」从 `ask` + 手动判断里解放出来。

| 函数 | 返回 | 说明 |
|---|---|---|
| `ui.clear()` | null | 清屏（整块控制台） |
| `ui.clear_line(n?)` | null | 清掉当前行（`n` 给数字 = 清掉最近 n 行） |
| `ui.color(颜色, 文字)` | str | 上色后返回字符串；颜色：`red green yellow blue cyan magenta white gray` |
| `ui.progress(当前, 总长)` | null | 画进度条（同一行原地刷新）；`总长=0` 不画 |
| `ui.menu(标题, [选项])` | int | 画数字菜单，返回选中项下标（**从 0 开始**）；非法输入重问 |
| `ui.input(提示, 默认?)` | str | 带提示的输入（等价 `ask` 但返回字符串、不给 `ans` 赋值） |
| `ui.table(表头, 行列表)` | null | 对齐打印一张表；中英混排按显示宽度对齐 |
| `ui.bar(值, 最大, 宽度?)` | str | 返回纯文本进度条（不刷新，可自己拼） |
| `ui.title(文字)` | str | 返回带分隔线的标题样式 |
| `ui.spinner(开始/停止)` | null | 转圈动画（后台线程，`ui.spinner(false)` 停） |

#### 兼容与边界

- 控制台不支持颜色时（重定向到文件），`ui.color` 自动退化为**原文字**，不输出乱码；
- `ui.progress` / `ui.spinner` 在 IDE 控制台里也走同一套输出（IDE 认 `\r` 和 ANSI）；
- `ui.menu` 的返回值是**下标**，不是选项文字 —— 这样可以直接 `match` 或 `if`。

#### 示例

```copper
import ui

int 选 = ui.menu("主菜单", ["开始游戏", "读取存档", "退出"])
if 选 == 0
    print(ui.color("green", "开始！"))
elif 选 == 2
    os.exit(0)
```

### 3.7 `re` —— 正则

| 函数 | 返回 | 说明 |
|---|---|---|
| `re.findall(正则, 文本)` | list | 所有匹配的**完整文本**（有捕获组时返回组文本） |
| `re.match(正则, 文本)` | dict / null | 从**开头**匹配；返回 `{text, start, end, groups: {名字/序号: 文本}}` |
| `re.search(正则, 文本)` | dict / null | 任意位置找第一个 |
| `re.test(正则, 文本)` | bool | 有没有匹配（等价 `search != null`） |
| `re.replace(正则, 替换, 文本)` | str | 全部替换；`$1` / `${名字}` 引用捕获组 |
| `re.split(正则, 文本)` | list | 按正则切分 |
| `re.escape(文本)` | str | 把特殊字符转义成字面量 |
| `re.compile(正则)` | 正则对象 | 预编译，可复用：`p.findall(文本)`（v1 可先不做，留位） |

#### 语法范围（重要）

TS 用 `RegExp`、Rust 用 `regex` crate，**两者语义不完全一样**，所以 v1 明确只承诺这一层：

- 支持：字符类 `[a-z]`、`\d \w \s`、量词 `* + ? {n,m}`、分组 `( )` 与命名 `(?P<名>)`、
  锚点 `^ $ \b`、或 `|`、非贪婪 `*?`；
- **不支持**：反向引用 `\1`、前后瞻 `(?=)` `(?!)`、`\p{…}`（Rust 的 regex 不支持前两者）；
  用了这些一律报错：「这个正则用了 Copper 不支持的语法：前后瞻」。

#### 示例

```copper
import re

str html = "<a href=\"/a\">甲</a> <a href=\"/b\">乙</a>"
list 链接 = re.findall("href=\"([^\"]+)\"", html)
for u in 链接
    print(u)          /* /a  /b

print(re.replace("(\\d+) 元", "$1 块钱", "共 30 元"))   /* 共 30 块钱
```

## 4. 第二批：`net`

> 排在网络与图形之前、7 个之后：它依赖 `json`（返回体解析），但不需要图形层。

| 函数 | 返回 | 说明 |
|---|---|---|
| `net.fetch(网址, 头?)` | str | GET，返回正文；`头` 是可选的字典 |
| `net.post(网址, 内容, 头?)` | str | POST；`内容` 传字典时自动按 JSON 发并带 `Content-Type` |
| `net.request(方法, 网址, 内容?, 头?)` | dict | 通用：`{code, body, headers}` |
| `net.download(网址, 保存到)` | bool | 下载到文件（大文件不占内存） |
| `net.encode(文本)` | str | URL 编码 |
| `net.decode(文本)` | str | URL 解码 |
| `net.query(网址)` | dict | 取查询参数 |
| `net.listen(端口, 处理函数)` | null | 起一个 HTTP 服务（**阻塞**）；处理函数收 `{method, path, body, headers}`，返回字符串或字典 |
| `net.server_close()` | null | 关掉 `listen` 起的服务（配合 `ui`/线程用） |
| `net.ip()` | str | 本机局域网 IP（给同宿舍联机用） |

约定：

- 超时默认 10 秒，可传 `{timeout: 30}`；
- HTTP 状态码 >= 400 时 `fetch` **抛错**（错误里带状态码和正文前 200 字），
  要自己处理就用 `net.request`；
- 明文 HTTP 允许（教学场景），HTTPS 走系统证书。

## 6. 实现顺序与验收

### 6.1 顺序（按依赖，不按喜好）

1. **os**：把 18 个函数搬到命名空间 + 补 14 个新的（共 32）；旧名保留。搬完跑一遍全量对拍（这一步最容易踩到路径语义）。
2. **data**：纯语言层，无 IO，最快出成果；`sort_by` 先做（用户最需要）。
3. **json**：复用 AOT 的 `parse_data` 解码器，双引擎共用一份语义。
4. **time** / **random**：都小，一起做；`seed` 要和 `ask` 重放语义一起测。
5. **ui**：只涉及输出与输入，注意 ANSI 兼容与「重定向时退化」。
6. **re**：最麻烦的是**语法子集对齐**，先把「不支持语法要报错」做好，再实现功能。

### 6.2 每个库的验收标准（缺一不可）

- [ ] 函数表里每一行都有实现（表即合同，不留「文档有、代码无」）；
- [ ] TS 解释器 / Rust VM 输出逐字节一致（`tests/parity/cases*.txt` 覆盖每个函数至少一条）；
- [ ] AOT：`call_builtin` 路径能跑；带回调的（`data.map` / `data.filter`）额外验一次；
- [ ] 错误文案统一中文、指出**哪个参数**、**实际给了什么**；
- [ ] 补全里有 `sig` 和 `doc`（点开就知道怎么用），示例进教程而不是只躺在文档里；
- [ ] 旧名字仍能用（迁移类函数），且补全里不再出现旧名。

### 6.3 明确不做（v1）

- 包管理器 / 在线下载库（PyPI 那种）—— 标准库先自带；
- 第三方依赖、版本冲突解析；
- 异步 / 并发原语（`await`、线程池）；
- 时区数据库、国际化。

### 7.1 真能用 / 有前提 / 没做

| 分类 | 内容 |
|---|---|
| ✅ 全平台纯计算 | `data.*` `json.*` `time.*`（换算与格式化）`random.*`（含固定种子可复现）`re.*` `ui.bar/title/table/color/progress/clear` `os.basename/dirname/extname/pathjoin` |

### 7.2 F6 怎么拿到宿主能力

TS 引擎跑在 WebView 里，本身读不到文件、环境变量、进程号。为了不让「同一个脚本 F5 能跑、F6 报错」，
新增了三个 Tauri 命令（`scaffold/src-tauri/src/commands/host.rs`）：

- `host_info`：pid / platform / cwd / temp / home / ip / args / 环境变量快照（前端缓存，只问一次）
- `host_setenv` / `host_run_cmd`：设环境变量、跑命令（工作目录跟脚本一致）
- `host_fetch`：HTTP 走宿主（ureq，10 秒超时）——WebView 自己的 `fetch` 会被 CORS 拦，这条和 Rust 内核同一条路

浏览器预览里没有这一层，所以文件/网络函数会明确说「桌面版功能」，不会假装成功。

### 7.3 两个引擎的数字格式必须一样

`print` 小数以前 TS 走 `toFixed(10)`、Rust 走 `round(1e12)`，同一个平均值两边差几位。
现在两边统一成：整数值直接打整数，其余四舍五入到 1e-12 —— 这是对拍能逐字比的前提。

## 8. 一句话总结

v1 不是「把 Python 标准库抄一遍」，而是**把写脚本和做游戏真正会用到的那 7 层补齐**：
文件系统（os）、数据加工（data）、数据交换（json）、时间（time）、随机（random）、
控制台交互（ui）、文本提取（re）。做完之后，成绩统计是 `data.sort_by` 一行，
爬网页是 `net.fetch` + `json.parse` + `re.findall` 三行。
