# Float IDE

> 小方工作室出品 ｜ Windows 桌面 ｜ MIT ｜ 完全免费 ｜ 当前版本 1.7.1

**Copper 语言工作室：给 Copper（原 CW Script / 代码世界）一个正经的 IDE。**

**Copper**（铜，原名 CW Script / 代码世界）是一门行式中文脚本语言：一行一句、缩进成块、指令写结果进特殊变量。原版配套的 IDE 是一个网页沙盒，写代码、打断点都施展不开。Float IDE 把它重做成一个真正的桌面 IDE：Monaco 编辑器、文件树、断点调试、变量查看、真终端、Git，一样不少。

0.2 把语言内核整个换掉了——不再是"一行一条正则"，而是 **词法 → AST → 解释器** 三层。所以 `for` 的次数能写变量、函数能有参数和返回值、类能继承。

## 标准库：`import 库名` 就能用

不用下载、不用装包，写一行 `import data` 就等于"我要用这个库"。函数是带库名的，
写全了才认得（`data.sum(xs)`），补全里输入 `data.` 就会把 26 个函数列出来。

```copper
import data
import json

list 学生 = [{"name": "老陈", "score": 88}, {"name": "阿方", "score": 93}, {"name": "小北", "score": 78}]

for s in data.sort_by(学生, "score", "desc") {
  print(s["name"] + " " + str(s["score"]))
}
print("平均 " + str(data.avg(学生, "score")))     /* 86.333333333333
print("中位 " + str(data.median([78, 88, 93])))  /* 88

var 数据 = json.parse(readfile("成绩.json"))
print(json.pretty(数据))
```

| 库 | 能干什么 |
|---|---|
| `data` | 排序（含按字段）、求和/平均/中位数/标准差、去重、频次、切片、拍平、zip、字典合并 |
| `json` | `parse` / `stringify` / `pretty` / `valid` / `try_parse`（坏 JSON 不炸，返回 `{ok, error}`） |
| `time` | `format` / `parse` / `parts` / `iso` / `diff` / `mark` + `since` 计时 |
| `random` | `rand` / `float` / `choice` / `shuffle` / `sample` / `gauss` / `weighted`，`seed` 之后可复现 |
| `re` | `findall`（带分组提取）/ `replace` / `split` / `test` / `escape` |
| `ui` | `bar` / `progress` / `table`（中文按 2 格对齐）/ `color` / `title` / `clear` |
| `os` | 文件、目录、路径（`basename` / `dirname` / `extname` / `pathjoin`）、环境变量、`runcmd` |
| `net` | `fetch` / `post` / `download` / `request` / `encode` / `decode` / `query` / `ip` |

旧名字（`readfile` / `now` / `fetch` / `sorted` …）全部保留，和 `os.readfile` 这类新名字是同一份实现。
文件与网络要桌面版（F5/F6 都行），浏览器预览里会明确说"桌面版功能"。

## 原生编译（AOT）：把 .co 编成真正的 exe

Copper 现在有两条执行路：**VM（默认，F5/F6 用）** 和 **AOT（原生编译）**。

```bash
cd scaffold/src-tauri/float-lang
cargo run --release --example aot /* 你的脚本.co -o 程序.exe --run
```

它做的事：源码 →（import / 宏展开）→ AST → **Rust 源码** → rustc -O3 → 本机 exe。
翻译层是纯新增模块（`src/aot.rs`），VM、词法、语法、AST 一行没动。

**语义和 VM 完全一样**：算术/比较/下标/成员/方法全部复用 VM 的实现；
作用域规则照旧（块里声明的变量块外可见、for 变量活到循环外、函数局部出不来）。

**实测（同一台机器，扣除进程启动开销）**

| 用例 | VM | AOT | CPython |
|---|---|---|---|
| fib(30) 递归 | 93.1 ms | **33.7 ms** | 124.4 ms |
| 循环累加 500 万 | 79.5 ms | **0.8 ms** | 139.9 ms |
| 字符串拼接 5 万 | 0.9 ms | **2.5 ms** | 3.0 ms |

fib 是 CPython 的 **3.7 倍**、VM 的 2.8 倍；循环被 LLVM 直接算成了闭式解。
字符串拼接两者同一档（VM 有就地追加，AOT 走同一份 `compound_value`）。

**AOT 不支持什么（编译期明确报，自动回落 VM 跑，结果不变）**

- 指针 `&` / `*`、`alloc` 之外的裸内存操作
- `ask`（需要交互宿主）、`wait until`、`time read`
- 函数里再定义函数、try 块里带 return/break/continue
- 用到这些的脚本会打印「AOT 暂不支持：…（第 N 行）」，然后照常用 VM 出结果

**大工程：分块 + 增量编译**

整份程序塞进一个 `.rs` 时，代码上到一两万行，单个 rustc 会吃掉几个 G 内存（实测把整台机器顶崩）。
超过体积闸门后自动切换成**分块编译**：

```
rt/        运行时（值模型/算术/方法/函数注册表）—— 永远不变，编一次就缓存住
chunkK/    每块最多 200 个函数，跨块调用走运行时注册表（块内调用仍是直接调用）
dataK/     超大表格（几百上千行的地图/敌人表）编成一段紧凑数据串，运行时一次解析
initK/     顶层语句超过 120 条时按组拆开
app/       顶层代码 + main + 装配
```

关键点：
- **只重写变了的文件**（内容比对），未改动 crate 的 cargo 产物直接复用 —— 这就是增量
- 大表格用 `parse_data(...)`：编译期瞬间完成，运行时解析 2000 行约 0.5ms
- `-j 2` 限制并行：一次开十几个 rustc 会把内存打满开始 swap，反而更慢

实测（6.3 千行游戏：2000 行地图 + 1000 条敌人表 + 500 个规则函数）：

| 场景 | 耗时 |
|---|---|
| 首次编译（含依赖） | ~47 s |
| 什么都没改 | **0.4 s** |
| 改一个函数 | ~34 s（其中约 28 s 是最后的链接） |

**正确性怎么保证**：`examples/aot_parity.rs` 把对拍用例逐条用 VM 和 AOT 跑一遍比输出；
`tests/aot.rs` 是翻译层回归（10 条，含分块结构、紧凑数据、跨块调用）。两者都进 CI 前的手工清单。

## Copper 写法速查：新代码推荐写法（legacy 对照）

Copper 保留了一批旧写法做兼容（老 .cw 文件不用改也能跑）。**新代码请一律用左列**；
右列是 legacy，能跑但教程、补全、示例都不再使用，迟早会收进「仅兼容」名单。

| 场景 | ✅ 新代码推荐写法 | ⚠️ legacy（仅兼容，别在新代码里用） |
|---|---|---|
| 定义函数 | `fn 名字(参数)` | `function 名字` / `func 名字` / `define 名字` |
| 列表追加 | `xs.push(x)` | `add x to xs` |
| 排序 | `xs.sort()` 就地 / `sorted(xs)` 返回新列表 | ——（两种都是正式写法） |
| 字典字面量 | `{"k": v}`（也可省花括号，但别省） | 裸 `k: v` |
| 取地址 / 读写 | `addr(x)` / `read(p)` / `write(p, 值)` | `&x` / `*p` / `*p = 值`（IDE 会提示换新写法） |
| 空值 | `null` | `nil` / `none`（**已取消**，写了会报错并提示改 `null`） |
| 跳出循环 | `break` | `out`（**已取消**，写了会报错并提示改 `break`） |
| 输出 | `print(值)` | `print 值`（括号可省是历史习惯） |
| 实例化 | `new Hero("阿方")` 或 `Hero("阿方")` | ——（两种都算正式写法） |
| 旧扩展名 | `.co` | `.cw`（打开 / 运行 / import 双候选，永久兼容） |
| 中文关键字 | 英文正式名（`readfile` / `now` / `report`…） | 中文别名（`读文件` / `现在` / `报告`…只保留兼容，不进补全不进文档） |

原则一句话：**教程和示例里出现的就是推荐写法**；不在教程里的写法都是兼容层，别教给别人。

## 1.6 这次改了什么（改名 Copper + 全链路大改）

这一版把语言正式改名为 **Copper**（铜，原 CW Script / 代码世界），源码扩展名从 `.cw` 换成 `.co`，旧的 `.cw` 全部照常能开、能跑、能搜。改动不止前端：Tauri 后端和 Rust 语言内核也一起动了。

### 语言：真指针 + 一批语法补齐

- 🧷 **`ptr` 变成真指针**：`&x` 取地址、`*p` 读、`*p = 值` 写、`**pp` 连续解引用；`p + 1` 按「格」平移，共享同一块内存（和 C 里地址加一个元素大小是同一件事，但越界会报错，不会踩内存）
- 🧱 **手动内存 `alloc(n)` / `free`**：`alloc` 出来的块自己还；`&列表[i]`、`&变量` 拿到的地址不能 `free`（报「这不是 alloc 出来的内存…」）
- 🕳️ **悬空指针检测**：函数返回后，指向它局部变量的指针会当场报错，而不是读到脏数据
- ✂️ **指针可迭代**：`for x in 指针` 从当前位置走到块尾；`len(指针)` 给剩余格数
- 🔤 **`and` / `or` / `not` 关键字**：等价 `&&` / `||` / `!`，短路语义一致；前面是 `.` 时不转换（`obj.not` 仍是成员名）
- ➗ **中缀 `mod`**：`a mod b` 就是取余，同时保留 `mod(a, b)` 函数写法
- 🧹 **缩进报错说人话**：直接告诉你「上一行缩进 4 个空格，这一行只有 2 个，还差 2 个」
- 💬 **`if` / `elif` 之间可以夹注释和空行**，不再因此断链报错
- 📦 **import 认双扩展名**：省略后缀时先找 `.co`，再回退 `.cw`
- 🧪 **双内核同步**：Rust VM 补了 `AddrLocal / AddrGlobal / AddrIdx / Deref / StoreDeref` 一组指针指令，TS 解释器与 Rust VM 跑同一套 parity 用例（新增 cases9 / cases10，以及 pointer / escape 独立测试）
- 🐱 **吉祥物彩蛋**：第 27 行报错变成「喵～第 27 行瘸了…」（TS 与 Rust 内核都有，Rust 侧带单元测试）

### IDE（前端）

- 📄 **新增文件内建**：`readfile` / `writefile` / `appendfile` / `hasfile`，走统一的 FsBridge，F5（Rust 内核）和 F6（解释器）行为一致；浏览器预览里会明确提示「文件功能要在桌面版里用」
- 🔄 **磁盘热更新**：AI 或别的编辑器在盘上改了 `.co / .cw / .json / .txt / .md / .in`，一秒多内自动灌进打开的缓冲区——缓冲区没改过才灌，你正在写的版本绝不悄悄覆盖
- 🖱️ **文件关联**：「关于」页可以一键把 `.co` 关联到 Float IDE，走 Win32 注册表写用户级 HKCU（不要管理员、不依赖 `reg.exe`），资源管理器里显示 Copper 猫图标；也可以查询、取消。双击 `.co`、把文件拖到 exe 上都能直接打开

## 补丁（1.6.0 之后）：变量作用域大修

这一轮只干一件事：把「变量到底活到哪」这件事在 **F5 编译通道 / F6 解释器 / Rust 内核** 三边彻底对齐，不再各说各话。

- 🔁 **`for` 循环变量活到循环外**：`for i in range(3)` 跑完，`print(i)` 给 `2`，不再报「没有定义」；`for x in 列表` 同理。外层本来就有同名变量时，循环会复用它（`int i = 99` → 跑完是 `1`），不会另起一个。
- 🧱 **循环体里声明的变量留在当前作用域**：和 `if` / `while` 的规则一致，出了循环照样能用。
- 🚫 **函数局部变量不再外泄**：Rust VM 以前读到没赋过值的全局槽会悄悄给 `null`，现在直接报「变量「local」没有定义（先声明或赋值）」——打错名字能当场发现，而不是拿到一个假值继续跑。
- 🏗️ **类可以省略 `new`**：`C()` 和 `new C()` 等价；Rust 编译器会先找对应的构造函数，找不到才按普通函数调用。
- 🔗 **`new C().get()` 能链式调用**：实例化之后还能继续接 `.成员` / 调用 / 下标，之前 Rust 解析器只吃到 `new C()` 就停了。
- 🧾 **F5 顶层循环变量写进 `$.v`**：不再生成裸 `let i`，避免顶层循环变量和脚本变量表打架。
- 📖 **教程新增「作用域：什么活到块外，什么出不来」**：三条规则 + 可运行示例，还补了「列表 / 字典按引用传，但重新赋值不影响外面」的说明。
- 🧪 **测试**：新增 `float-lang/tests/scope.rs`（循环变量、嵌套同名循环、块内声明、局部不泄漏、全局读写与遮蔽、列表/字典传参、类字段与方法局部同名）；parity `cases10.txt` 与 `pointer.test.ts` 补作用域用例；`correctness.rs` 增加「读未定义变量必须报错」断言。
- 📊 本轮 11 个文件、+135 / −15 行。

## 0.7 这次改了什么（抗造版本）

这一轮的主题是**「自己找 bug」**：专挑会让 IDE 崩、会悄悄丢代码的地方下手。

| 方向 | 问题（原来） | 现在 |
| --- | --- | --- |
| **两个进程冲突** | 两个 Float IDE 同时开同一个工程，互相覆盖谁也不知道 | 工程级心跳锁：第二个窗口打开时明确提示「已有一个 Float IDE（进程 N）在编辑」，不抢锁；崩溃强杀也能自愈（12 秒无心跳自动释放） |
| **文件被外部改动** | 写盘直接覆盖，别人的修改无声消失 | 写前校验 mtime，不一致就挂起并弹条：「已被另一个程序修改」→ 用户选**仍要覆盖**或**放弃我的改动重新加载** |
| **半截文件** | `fsWrite` 直接写目标，读到一半内容的窗口会拿到坏文件 | 改成原子写（临时文件 + rename），任何时刻读到的都是完整内容 |
| **连点运行** | `ctl` 是异步状态，连按 F5 能起两个 Runner，控制台串味、状态错乱 | 同步闸门 + 每次运行发令牌，旧 Runner 的回调一律丢弃；开跑前先掐掉上一个 |
| **保存撞车** | Ctrl+S 与自动保存同时写同一文件；保存期间继续敲的代码会被标成已保存而丢掉 | 单文件写盘串行化 + 内容快照校验：只有「期间没再改动」才清脏标记 |
| **语言核心绑死 DOM** | `interp.ts` 直接用 `window`，换个宿主就崩 | 宿主探测（`window` → `globalThis`），同一份运行时在浏览器 / Node 都能跑 |
| **自引用容器** | `list a = [1]` + `add a to a` 之后 `print a` / 拷贝 / 比较 → 爆栈崩掉 | 环检测：打印成 `[1, …(循环)]`，拷贝与比较保持结构 |
| **无限递归** | 报一句引擎的 `Maximum call stack size exceeded`，没行列、看不懂 | 统一上限 400 层，两条执行通道都报：「递归太深了（超过 400 层）… 多半是 f() 的结束条件没写对」 |
| **静默通过的坏代码** | `if` 不写条件 → 整段分支变成永不执行的死代码；顶层 `return` / `out` 被悄悄吞掉 | 全部给出诊断 |
| **print 语法** | 只有 `print(x)` 能用，`print x` 报「看不懂」 | 括号可选，`print n` / `print a, b` 都可以 |

**长代码实测**（`npm run test:stress`，17 项全过）：

- 4705 行（300 函数 + 50 类 + 3000 变量）解析 34ms、静态分析 26ms、执行 53ms，结果正确
- 2 万行单文件解析 + 执行 130ms；2 万元素列表、2 万次字符串拼接均正常
- 括号嵌套 600 层、缩进嵌套 150 层均可解析
- 13 种残缺语法全部有诊断，0 个静默通过

## 语言十行上手

```text
class Hero
    str name = ""
    int hp = 100

    function init(name)
        self.name = name

    function hurt(damage)
        hp -= damage
        return hp

Hero h = new Hero("阿方")
print(h.name + " 剩余 " + h.hurt(30))
```

要点（详见 `language/catalog/core.json`）：

- **一行一句**：缩进定块，`{ }` 可写可不写，`/*` 开头整行跳过
- **表达式到处能用**：赋值右值、`print`、`if`/`while` 条件、`for` 的次数、函数参数都走同一套解析
- **循环变量真可用**：`for i in range(n)` 里的 i 每轮绑定，嵌套循环各用各的
- **函数**：`function name(a, b = 1)` 定义，`name(1)` 调用，`return` 返回值，可递归
- **类**：`class Name` + 字段 + `init` + 方法；`new Name(…)` 创建；方法里字段可裸名读写
- **特殊变量**：`add / lt / join / read / time read` 等指令的结果仍写进 `__last_calc / __last_cmp / __last_str / __last_read / __last_time`；`ask` 的回答存 `ans`
- **条件运算符**：用 `> < == != && || !`，也支持 `and / or / not` 关键字写法（等价）
- **import**：`import "lib.co"` 按文件，`import "tools"` 按文件夹（找 `tools/main.co`）

十七份示例在 `language/samples/`，从 hello 到类与继承，再到手动内存、指针游戏与《方岛物语》开放世界。

## 常见问题

**F5 和 F6 结果一样，速度差那么多？**
F5 把代码编译成 JS 跑（快），F6 用解释器逐行跑（能停、能看变量）。语义是一套，结果相同。

**双击没反应 / 白屏？**
确认装了 WebView2（Windows 11 一般自带）。自己构建的先在 `scaffold/` 里 `npm install`。

**运行没反应？**
看控制台报错。语法有错时会先列出全部错误行，改完再跑。

**调试时断点不停？**
断点在调试模式（F6）才生效，直接 F5 运行是不停的。改完代码记得 Ctrl+S 再跑。

**类的方法里为什么能直接写 `hp` 而不是 `self.hp`？**
这是有意设计：方法内先找局部变量，再找当前对象的字段。写 `self.hp` 更明确，两种都行。

**和原版 Copper 工程通用吗？**
脚本语法向下兼容；原版网页里的舞台 / 角色相关指令不在本语言范围内。原版参考材料在 `reference/`。

## 近期更新

### 1.7.1（2026-11-05）

- **AOT 崩溃根治**：生成函数体时全局槽会动态新增，之前嵌套 `for` 场景下可能越界 panic；现在按最终代码反推「至少需要的槽数」，宁可多开也不崩。
- **资源上限**：列表（100 万项）、字典（50 万键）、字符串重复等加软上限，超限给一句人话报错，不再卡死或内存爆掉。
- **值循环引用防护**：变量快照与查看时主动打破循环引用，避免遍历卡死。

### 1.7.0（2026-11-04）

- **注释与自减冲突解决**：注释统一 `/*`（写到行尾、不用闭合）；`--` 只作自减运算符，旧写法报错并提示改法。
- **`//` 改为整除运算符**，内建 `idiv` 保留兼容。
- **指针全面完善**：`&` 取地址、`*` 解引用与写回、指针运算、`p[i]` 寻址、`for … in` 遍历、`alloc`/`free`；悬空与越界当场报错。
- **语义收紧**：类名当函数调直接拦截并提示 `new`；`stop all / now / script` 合并为 `stop`。语言规范 0.5.0。
